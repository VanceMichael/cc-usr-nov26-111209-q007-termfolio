# 本地字符台账

真实交互入口为 `python3 -m termfolio.ledger --update-after-details 1`，需连接 PTY，固定屏幕24行80列。中文为本程序逻辑单格字符，不实现宽字符规则。支持 ANSI CUP、ED2、EL0、SGR 和 CR/LF；字符可能按多次系统写入交付。回放 fixture 仅用于屏幕投影测试，不能代替交互采集。

n/p 翻页，j/k 移动焦点，o 打开当前行详情，b 返回，q 退出，模态提示按空格确认。列表每页三行，相邻页重叠一行，详情返回后焦点回第一行。列表包含摘要，详情才有完整箱号及备注；屏幕第24行是版本、页号和就绪信息，第2行时钟每0.2秒局部刷新，不应作为完成翻页依据。m 和 s 是受保护写入入口，本地程序会显示禁止访问，采集不能触发。输入非法按键时只更新状态行。

--update-after-details=1 会在第一次详情返回后弹出资料更新提示，确认后改为v2并重置首页；v2新增一个箱号。参数为0时版本稳定。源程序直接合成台账用于隔离演练；生产采集只依据 PTY 屏幕及合法按键，不读取 ledger.py 的行记录作为输入。项目不包含网络终端协议、真实账户或外部设备。

## PTY 采集边界

`termfolio collect` 是唯一的交互采集入口，边界如下：

* 采集进程通过 `pty.openpty` 启动台账子进程，只持有 PTY 主从文件描述符；不打开、不解析台账程序的任何数据文件，也不修改 ledger.py 增加数据接口。测试与生产路径都只消费渲染后的 24x80 屏幕单元格。
* 驱动层 `ALLOWED_KEYS` 限定为 n/p/j/k/o/b/空格/q，任何其他字节在发送前抛出 `IllegalKey`，m 与 s 永远无法到达台账程序。
* “刷新完成”由结构静止判定：屏蔽第 2 行时钟后，整屏快照连续 `settle` 秒不变且状态行可解释才返回；局部覆盖、ED2/EL0 清屏都在投影器中还原成最终单元格，不依赖原始流关键字，也不使用固定 sleep。
* 版本以第 24 行状态行为准。更新模态确认导致版本号变化时，当前内存结果整体作废（journal 保留 `version_reset` 与作废清单），新会话从首页重采；导出末尾再次校验所有条目同属目标版本，否则失败而不是出混合结果。
* 重叠页不丢不重：每条详情观察都入 journal，导出按完整箱号合并，sources 保留每次出现的页、焦点及详情/返回屏幕快照引用；同箱号备注或版本不一致即停止。
* 运行目录是可重建证据包：raw 原始字节流可用 `termfolio replay` 或 inspect 重新投影，screens 是每次决策依据的整屏文本，keys 与 journal 使每一行都能追溯到具体按键序列和屏幕状态。
* 中途退出（q）后重入同一运行目录：先核对版本，再逐页 n/p 核对页号与焦点定位；任一项不符即失败并落盘可见屏幕。失败状态的运行目录拒绝继续，必须人工接手后新建运行。
